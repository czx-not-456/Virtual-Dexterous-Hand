## 2. 必须修改或补充的具体文件

### A. 复现路径错误

涉及：README_先看这里.md、复现实验.py、验证成果.py、实时演示.ps1；图册最后的复现说明也需同步。

实际目录位于“项目进度报告相关文件/中期检查/项目中期成果/中期增强成果V2”。两个实验/验证 Python 脚本却使用 ROOT=HERE.parent，实时演示脚本也切换到其父目录；由此定位不到项目根目录的 test、src、datasets、数据手套数据和 .venv。README 中“中期增强成果V2/...”的命令同样假设该目录直接位于项目根目录，照抄不能运行。

修改：保持材料所在位置，改为向上查找同时具有 pyproject.toml 和 src 目录的项目根目录，并在找不到时明确报错。PowerShell 用同样的根目录检测方式。README 中的脚本路径改为实际的完整相对路径，并说明从项目根目录运行。不要为了迁就脚本而直接移动整包到项目根目录。生成图册.py 本身使用 HERE/结果，未发现同类 ROOT 定位错误；但它依赖前两步的有效输出。

README 还同时写着“已有虚拟环境不要重复创建”并紧跟创建 .venv 的命令，建议将新建环境与复用环境分成两种步骤。新增绘图等依赖在当前项目 .venv 中尚未安装，这不是脚本逻辑错误，但须明确安装 requirements-v2.txt 的实际路径；本次核查没有安装包或修改环境。

### D. 08 两张任务时序图含义及内容需补充

涉及：结果/08_pinch_任务时序.png、08_wrap_任务时序.png；复现实验.py 的 benchmark()；图册图4、图5及说明。

1. 顶部“指尖距离”读取 pinch_distance_m。src/features/feature_extractor.py 表明它由人体手模型的拇指、食指指尖计算，wrap_score 是非拇指归一化屈曲均值。应分别标明“人体手模型指尖距离”和“输入屈曲包络评分”，避免读者理解成 CH-M6 指尖实际间距或物体包络质量。
2. 接触/稳定曲线画出的是全程原始布尔值，因此在绿色任务有效区间以外也可能为 1；汇总占比则按有效任务帧统计。原始曲线本身不应认定为绘制错误，但必须说明“区间外原始值不计入该任务汇总”，或同时提供有效区间掩码后的曲线。图例放到轴外，避免遮挡有效区间中的线条。
3. 原 08 目录要求的物体姿态漂移、伺服误差尚未展示。原逐帧 CSV 已有 orientation_drift_deg、servo_mean_error_m 等字段，可增加相应子图并注明单位和无效/未启用区间。现在的两张图不能算完整完成原定展示项。
4. 历史文件的日期与指标定义应写在图注：2026-10-08 历史基线，不能与当前 StableGrasp-v2 混用。

### E. 13 号实验缺失通道口径待确认

涉及：结果/13_传感器缺失鲁棒性.png、13_六类手势混淆矩阵.png、13_设备泛化差异.png、三份 13 CSV、summary.json 的 recognition、README 新增实验方法、11_下一阶段计划.md、生成图册.py 及图册第六/七部分。

结果可按现有算法重现，但原始记录中 8 个 G12 序列号设备的 sensor_7、sensor_10、sensor_13 全为 0；4 个 G15 设备没有这种恒定列。代码统一在 15 列中随机屏蔽 1/3/5 列，可能屏蔽本来就不变的列。因此“共15路传感器、缺失5路仍96.84%”未充分说明数据条件，不能直接理解为所有设备都丢失了5路有效物理传感器。

目前文件只能证明这些列为常零，尚不能单凭序列号和数值断言它们是占位补零还是实际硬件通道。需向数据提供者确认设备通道定义、左右手列顺序和是否已经统一语义。若仅作为“统一15列数据表示上的随机屏蔽”试验保留，应在图注与正文明确写出常零列情况、混合设备条件及局限。若要主张真实有效传感器缺失鲁棒性，应依据确认后的物理通道掩码重算，按设备类型及实际失效有效通道数分层报告。

此处涉及实验目标选择，未自主删除列、改变分组或重算替代成绩。设备留出不等于被试留出；12个序列号也不应写成12名受试者。混淆矩阵为样本等权，99.58%为设备等权；原图册已区分，后续独立引用图片时也应保留此说明。
