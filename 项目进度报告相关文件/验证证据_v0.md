# 验证证据_v0

本文档根据《项目进度简报》梳理 Virtual-Dexterous-Hand-v0 中动作数据处理、姿态与特征建模、意图识别、动作映射、MuJoCo 虚拟灵巧手仿真及评测指标的实现位置与文档证据。

项目成果形成了一条较完整的软件链路，但相关证据分散在当前说明、设计依据、版本记录、验证报告、源代码与配置文件中，并非每项能力都有独立文档。

## 二、各类指标的具体位置

### 1. 数据处理指标

配置中的实际参数包括：

- 采样率：60 Hz；
- 输入通道：15 个关节通道；
- 滑动平均窗口：5 帧；
- 标定结果：各通道裁剪并归一化至 `[0,1]`；
- 输出低通：`alpha=0.45`；
- 最大输出速度：360°/s。

权威实现位置：

- [`configs/glove.yaml`](configs/glove.yaml)
- [`configs/algorithm.yaml`](configs/algorithm.yaml)
- [`src/glove/calibration.py`](src/glove/calibration.py)
- [`src/processing/filters.py`](src/processing/filters.py)

文档只给出整体概括，代码与配置才是当前精确参数。当前输入来自合成数据集或 Mock 驱动，真实数据手套驱动仍是未实现模板，因此这些处理能力尚未经过真实用户与真实传感器验证。

### 2. 姿态与特征指标

`FeatureExtractor` 每帧生成：

- `joint_angles`：15 维关节角；
- `joint_normalized`：15 维归一化关节角；
- `fingertip_positions`：五指指尖三维坐标；
- `wrap_score`：12 个非拇指关节归一化弯曲量的平均值；
- `pinch_distance_m`：拇指与食指指尖的欧氏距离。

具体公式位于 [`src/features/feature_extractor.py`](src/features/feature_extractor.py)。目前没有专门的特征设计文档，主要由 [PROJECT_BASIS.md](PROJECT_BASIS.md) 和《项目进度简报》进行概括。

### 3. 意图识别指标

实际识别逻辑使用：

- PINCH 进入阈值：0.060 m；
- PINCH 退出阈值：0.072 m；
- WRAP 进入阈值：0.68；
- WRAP 退出阈值：0.58；
- 7 帧短时序平均；
- 连续 4 帧满足条件才切换状态。

参数见 [`configs/algorithm.yaml`](configs/algorithm.yaml)，原理说明见 [LITERATURE_INFORMED_DESIGN.md](LITERATURE_INFORMED_DESIGN.md)。

需要纠正一处文档表述：当前 [`Intent`](src/features/intent_recognition.py) 实际只输出 `NEUTRAL`、`PINCH`、`WRAP` 三类。`OPEN` 是合成数据集中的动作阶段标签，识别器会将其判为 `NEUTRAL`，并不是第四个识别输出类别。因此 README 和进度简报中的“四类意图识别”表述不完全准确。

项目目前没有真实标注数据上的准确率、召回率或混淆矩阵，不能表述为“意图识别准确率已经达到某个百分比”。

### 4. 动作映射指标

映射目标函数包含：

```text
E = w_pos E_pos
  + w_vector E_vector
  + w_topo E_topo
  + w_smooth E_smooth
  + w_coupling E_coupling
  + w_collision E_collision
```

具体计算见 [`src/retargeting/optimizer.py`](src/retargeting/optimizer.py)，设计解释见 [LITERATURE_INFORMED_DESIGN.md](LITERATURE_INFORMED_DESIGN.md)。

仓库中存在两组不同版本的 Mock 对照结果：

| 版本记录 | PINCH 位置 MSE 改善 | PINCH 向量 MSE 改善 | WRAP 耦合改善 | WRAP 向量 MSE |
|---|---:|---:|---:|---:|
| v0.3 验证 | 9.58% | 40.03% | 83.64% | -41.77% |
| v0.3.4 测试报告 | 75.56% | 73.50% | 83.48% | -8.47% |

来源分别为：

- [VALIDATION.md](VALIDATION.md)
- [test_results_v034_20260914/TEST_REPORT.md](test_results_v034_20260914/TEST_REPORT.md)

这些结果均为合成或 Mock 数据下的工程对照结果，不是正式人体实验结果。不同版本的参数和实现已经变化，引用数值时必须注明对应版本。

### 5. MuJoCo 与接触指标

当前评测器输出的主要指标包括：

- `contact_frame_ratio`；
- `stable_frame_ratio`；
- `contact_success_proxy`；
- `stable_success_proxy`；
- `first_contact_latency_ms`；
- `p95_pipeline_latency_ms`；
- `mean_joint_rmse_rad`；
- `mean_velocity_rms_rad_s`；
- `mean_tip_contact_ratio`；
- `max_orientation_drift_deg`；
- `max_object_displacement_m`；
- `mean_servo_error_m`。

字段定义集中在 [`src/evaluation/task_evaluator.py`](src/evaluation/task_evaluator.py)，面向使用者的解释位于 [README.md](README.md)，接触指标的验收方法集中在 [CONTACT_VALIDATION.md](CONTACT_VALIDATION.md)。

需要注意：

- `contact_success_proxy` 只说明规定接触连续达到阈值；
- `stable_success_proxy` 还要求物体姿态漂移不超过 3°；
- 两者都不是“抓起并搬运成功”，因为当前手掌基座固定，没有抬升和运输阶段。

## 四、当前证据缺口

《项目进度简报》中记录了以下当前结果：

- 58 项自动测试全部通过；
- 六任务单 trial 为 6/6；
- P95 管线延迟约为 60.6–69.5 ms；
- WRAP、sphere、bottle、box 达到稳定接触代理；
- PINCH 和 card 达到双指接触代理，但没有达到自由物体稳定成功。

其中“58 passed”同时写入了 [README.md](README.md)，但项目当前的 `outputs` 目录没有保存与上述六任务结论对应的完整 `benchmark_summary.csv`、`BENCHMARK_REPORT.md` 和 HTML 看板。现有输出主要是较早的单任务运行结果。

因此，这些当前结论可以作为阶段进度说明，但尚缺少仓库内可追溯的完整运行产物。后续正式汇报前，建议重新运行标准 benchmark，并保存以下文件：

- `benchmark_runs.csv`；
- `benchmark_summary.csv`；
- `BENCHMARK_REPORT.md`；
- `benchmark_dashboard.html`；
- 对应单次运行的 CSV 和 summary JSON；
- 测试环境、依赖版本、执行命令与时间戳。

## 五、阶段结论

当前可以准确表述为：

> 项目已经实现从合成数据输入、标定与滤波、15 关节姿态和任务特征提取、规则及时序意图识别、意图驱动动作映射，到 MuJoCo 六任务接触仿真与指标评测的软件闭环。

但不能表述为：

- 已完成真实数据手套闭环；
- 已获得真实用户意图识别准确率；
- 已完成 CasiaHand 官方数字孪生；
- 已验证实体灵巧手映射精度；
- 已完成真实抓起、搬运和放置；
- 已获得正式实验意义上的抓取成功率。

总体而言，软件模块和评测框架已经实现，合成数据下的仿真闭环已经跑通；真实硬件、真实用户和正式实验仍是下一阶段的核心任务。
